# Dominionizer

An Angular progressive web app that generates randomized card sets for the board game Dominion,
deployed at [dominionizer.app](https://dominionizer.app/) and localized into many languages. All
card data comes from the [Dominion Strategy wiki](https://wiki.dominionstrategy.com/) and is
generated by the wiki bot in _tools/wiki-bot_.

## Domain vocabulary

- **Expansion** - a published Dominion box, for example Seaside or Rising Sun.
- **Edition** - a printing of an expansion. `Edition` carries both (`expansion: 'Seaside'`,
  `edition: '1'`), and players pick editions, not expansions, because the card pool differs between
  printings.
- **Kingdom card** - one of the ten cards that form the supply of a game. Flagged by
  `Card.isKingdomCard`.
- **Special card** - a card drawn alongside the kingdom: event, landmark, project, way, trait, ally
  or prophecy. Identified through `Card.types` and `CardTypeId`.
- **Dependent special card** - a special card that is only drawn because another card pulled it into
  the set: a Liaison pulls an Ally, an Omen pulls a Prophecy.
- **Set** - the generated result, `kingdomCards` plus `specialCards`.

## Repository map

- `src/app/components` - one folder per component, each with template, styles and spec
- `src/app/services` - the state layer; RxJS subjects exposed as `$` suffixed observables
- `src/app/models` - domain types
- `src/app/dtos` - the shape of the generated JSON as it is read from `src/data`
- `src/data` - **generated** card, edition and card type data, one set per language
- `src/assets/card_art`, `src/assets/card_symbols` - **generated** images
- `src/locale` - one `.xlf` message file per locale
- `src/testing` - fixtures, spies and stub components for tests
- `scripts/build.ts` - builds one bundle per language
- `tools/wiki-bot` - separate npm workspace, has its own `AGENTS.md`

## Commands

`package.json` lists the scripts. Three things it does not tell you:

- Run the tests with `npm run test:ci`. The plain `test` script watches and never returns.
- The wiki bot has its own suite: `npm run test:ci -w tools/wiki-bot`.
- CI runs `eslint`, `stylelint` and `markdownlint`. `prettier:check` is not part of it and already
  reports pre-existing findings in a handful of files, so a red result there is not yours.

## Generated data

Everything under `src/data` and the two card image folders is produced by the wiki bot. A wrong value
is fixed in the responsible builder in `tools/wiki-bot/src/wiki-bot/builder/`, never in the JSON - the
next bot run overwrites a hand edit and hides the cause. See `tools/wiki-bot/AGENTS.md`.

## Recurring tasks

- Writing or changing a spec: skill `writing-tests`
- Adding a locale: skill `add-language`

## Gotchas

- The husky `pre-push` hook runs the whole test suite, so pushing takes a while.
- An `eslint` run killed with SIGKILL ran out of memory. Lint a subset of the files instead.
- The wiki blocks ordinary requests behind a bot protection. Reaching `api.php` or `/images/...`
  needs the header `Dominion-Wiki-Client` with the token from `tools/wiki-bot/.env`.
